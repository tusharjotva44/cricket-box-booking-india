PRICING & ACCESS

Subscription Plans

Central plan configuration for owner accounts.

Subscription plan management is not connected yetThe current project does not have a shared subscription-plans collection or a server-validated plan purchase flow. Creating or editing plans in this page before that backend exists would only save browser-local data and could show different prices to different users. This section is intentionally read-only until the secure shared plan system is added.

Plan setup required

Monthly and yearly plan prices, duration, maximum grounds per owner, included features and active/inactive state need a shared Firestore collection and server-side validation.

Existing owner plan fields

Owner profiles currently contain fields such as planName, subscriptionStatus and trial dates. These can be reviewed in Owner Management, but are not a complete paid-plan ledger.

TRANSACTION RECORDS

Payments

Payment history and subscription collections.

No verified payment ledger is connectedThe current application does not save subscription payments in a dedicated Firestore collection and does not provide server-side payment verification. Booking payment fields shown in the owner interface are not a verified platform subscription transaction record. No revenue total is displayed until trusted payment records are available.

Payment records

A secure payment integration should store the gateway order ID, verified transaction ID, owner UID, plan, amount, currency, payment status and timestamps.

Verification

Payment success must be confirmed by a trusted server or payment-gateway webhook—not by a browser redirect or a value entered by an owner.
